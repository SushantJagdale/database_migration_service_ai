# AWS RDS Pre-Migration Data Collector Agents

This project contains a multi-agent system for collecting pre-migration data from AWS RDS MySQL and PostgreSQL instances. The agents are designed to check for prerequisites required for a successful Google Cloud Database Migration Service (DMS) continuous migration job and generate a consolidated HTML report.

## Setup

1.  **AWS CLI:** Ensure you have the AWS CLI installed and configured with a `default` profile that has the necessary permissions to describe RDS instances. You can configure this by running `aws configure`.

2.  **Google API Key:** Set your Google API key as an environment variable:
    ```bash
    export GOOGLE_API_KEY="your_api_key"
    ```

3.  **Python Environment:**
    *   It is recommended to use a Python virtual environment.
    *   Install the required packages:
        ```bash
        python3 -m venv .venv
        source .venv/bin/activate
        pip install -r requirements.txt
        ```

## Usage

1.  **Discover RDS Instances:**
    *   Run the `aws_utils.py` script to discover all RDS instances in your account and create a `db_list.txt` file. You can specify a region.
        ```bash
        python -c "from root_agent.aws_utils import list_all_rds_dbs; list_all_rds_dbs(region_name='us-east-1')"
        ```

2.  **Run the Root Agent:**
    *   The root agent will analyze your prompt and route it to the appropriate child agents (MySQL and/or PostgreSQL).
    *   Provide the prompt as a command-line argument to `cli.py`.
        ```bash
        python cli.py "Analyze all RDS instances in region 'us-east-1' and generate a report."
        ```
        or be more specific
        ```bash
        python cli.py "Analyze the PostgreSQL RDS instance 'postgres-db-1' in region 'ap-south-1' and the MySQL RDS instance 'mysql-db-1' in region 'us-east-1' and generate a report."
        ```

3.  **View the Reports:**
    *   The agents will generate Markdown reports for each database (`mysql_report.md` and `postgres_report.md`).
    *   A consolidated HTML report (`final_report.html`) will also be created.

## How it Works

The project uses a sequential multi-agent system to orchestrate the data collection and report generation.

1.  **Root Agent:** The `root_agent` is a `SequentialAgent` that orchestrates the entire workflow. It first runs the `db_checker_agent` and then the `html_generator_agent`.
2.  **DB Checker Agent:** The `db_checker_agent` is a `ParallelAgent` that runs the `mysql_dms_agent` and `postgres_dms_agent` concurrently.
3.  **Database Agents:** The `mysql_dms_agent` and `postgres_dms_agent` contain the logic for checking DMS prerequisites for their respective database engines.
4.  **HTML Generator Agent:** The `html_generator_agent` takes the Markdown reports generated by the database agents and creates a single, consolidated HTML report.
5.  **AWS Utils:** The `aws_utils.py` script contains helper functions for interacting with the AWS API using Boto3.

## Reports

The following reports are generated in the root directory:

*   `mysql_report.md`: A Markdown report of the findings for all MySQL instances.
*   `postgres_report.md`: A Markdown report of the findings for all PostgreSQL instances.
*   `final_report.html`: A consolidated HTML report of the findings for all database instances.

## GCP DMS Migration Setup Requirements

Before triggering the **Configure DMS Job** step in the frontend, you must ensure that the source database credentials have been populated in GCP Secret Manager in the target project. 

The backend agent retrieves these credentials dynamically to create the migration connection profiles.

### Credentials Secret Structure:
For each discovered source database (e.g., `gemini-mysql-instance-1`), create the following two secrets in Secret Manager:
1.  **Username Secret:**
    *   **Secret Name:** `{source_db_instance_id}_user` (e.g., `gemini-mysql-instance-1_user`)
    *   **Secret Value:** The database master/migration username (e.g., `admin`).
2.  **Password Secret:**
    *   **Secret Name:** `{source_db_instance_id}_password` (e.g., `gemini-mysql-instance-1_password`)
    *   **Secret Value:** The database password.

Ensure the service account running the backend application (or your active `gcloud` context if running locally) has the **Secret Manager Secret Accessor** (`roles/secretmanager.secretAccessor`) permission on these secrets.

### 4. Frontend UI Upgrades

*   **Automatic Region Mapping:** The dropdowns are dynamically populated with instances discovered during the AWS scan. Selecting a source database automatically maps the AWS region to its closest GCP region (e.g. `ap-south-1` maps to `asia-south1`) and auto-fills the GCP region selector.

### 5. DMS Configuration Fixes
*   **Gcloud Provisioning Argument Correction:** Resolved a target provisioning failure by updating the DMS agent command builder in `dbmigration_agent.py` to use the correct `--data-disk-size` flag instead of the invalid `--storage-size` flag.
