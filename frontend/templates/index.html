GCP DMS Migration Management
How to Use the Database Migration Hub
1. AWS Credentials 2. Database Discovery 3. Pre-Migration Report 4. Connection Validation 5. Start & Promote DMS

1. AWS Credentials Configuration

Securely configure access to your source AWS environment.

Prerequisites:

A 12-digit AWS Account ID and an IAM User Access Key ID / Secret Key with RDS read-only policies (e.g., AmazonRDSReadOnlyAccess).

Instructions:
  1. Click the AWS Widget on the home dashboard.
  2. Input your AWS Account ID, Access Key ID, and Secret Access Key.
  3. Click Configure AWS.
  4. The system validates the credentials with AWS Security Token Service (STS) before letting you proceed.

2. Database Discovery

Scan your AWS environment to find database instances.

Instructions:
  1. Clear or edit the Discovery Query input box.
  2. You can filter by engine or region (e.g., "Discover only mysql databases in Mumbai region").
  3. Click Discover Databases. The background agent will scan the target regions and test compatibility parameters.

3. Pre-Migration Assessment Report

Review compatibility scores and flags before starting a migration.

Instructions:
  1. Read the parsed Pre-Migration Report generated for each instance.
  2. Check the flags for connectivity, replication slots, binlog settings, and engine versions.
  3. Address any highlighted flags in your AWS Console before initiating migration.

4. Target Connection Validation

Confirm that Google Cloud can reach and authenticate with your source RDS database.

Instructions:
  1. In Step 4 (Migrate), select your target database instance from the dropdown.
  2. Input the source database Port, Username, and Password.
  3. Click Validate Connection to run port-level and login verification checks.

5. Start & Promote DMS Job

Configure, trigger, monitor, and finalize your database migration.

Instructions:
  1. Click Configure DMS Migration Job to build connection profiles on GCP.
  2. Click Start Migration Job to launch the full-load stage.
  3. Review the status board. Once replication lag drops to 0, click Promote Database to complete cutover and finalize the migration.
